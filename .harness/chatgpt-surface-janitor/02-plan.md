# Approved implementation plan — chatgpt-surface-janitor

This C2C-approved Step 3 plan authorizes no source implementation until the next canonical Human Gate approves the visual plan.

## Plan

1. Make `c2c janitor` machine-wide. Read every valid local binding and exact-resource reference; accept and ignore leftover `-w <anything>` while reporting machine-wide scope. Require stable ChatGPT-side ID, kind, safe metadata, and capability outcome for `project`, `plugin`, `custom_mcp`, and `connector`; never select by labels, prefixes, ordinals, wildcards, absent, or conflicting identity. Use versioned exact protection mapping, preserving legacy name-only records as non-exact and letting exact keep/protection override deletion intent.
2. Before janitor domain work, add a read-only feasibility probe for a repository-owned Node child process launched by `c2c janitor` with line-delimited JSON over inherited stdio. Declare `playwright` and Chromium, use an owner-only dedicated janitor profile, and never attach to a user Chrome or ChatGPT-desktop profile. It opens first-party ChatGPT visibly only for human login or supported 2FA, returns `AUTH_REQUIRED` without attempting credentials/recovery/2FA, uses semantic locators only, and returns bounded `CAPABILITY_UNAVAILABLE` when its browser/origin/account/enumeration preflight fails.
3. Use a strict owner-only janitor store: versioned allowlisted DTOs, missing-versus-malformed errors, atomic temp-file/rename writes, permissions, and bounded retention. Persist stable IDs and safe metadata only; exclude private URLs, raw account data, cookies, tokens, storage, screenshots, and content. `scan` uses runtime-owned `ConnectionBinding.accountFingerprint` only after current machine-verified surface evidence matches it. Inventory includes protection/reference status, classification, and reason. Exact protected/keep entries are `keep`; only eligible non-protected entries begin `unknown` and may be edited to `delete`.
4. Canonically digest schema version, inventory ID, account fingerprint, and exact actions, excluding derived digest/history/timestamps/outcomes. `dry-run` has no surface calls and prints its digest, exact delete IDs/names, plus keep/unknown/protected/stale/ambiguous totals. `apply --plan-digest` re-reads, validates, canonicalizes, recomputes, and compares that digest and current account authority before driver access.
5. Make deletion identity-bound. `prepareExactTarget` returns an in-memory random, short-lived, one-shot token bound to companion session, stable ID, kind, metadata, and account fingerprint. An owner-nonce, crash-recoverable cross-process apply lease rejects concurrent apply. A finalization lease, shared by all binding/provisioning/app-selection/reference writers, spans the final protection read through click. `confirmPreparedRemoval` re-observes the account at the exact semantic control and requires a match before consuming the token, while also reasserting ID/kind/metadata. Logout, stale/mismatched account, replay/expiry/wrong session, new protection, drift, ambiguity, or unsupported route fail closed. Atomically record outcomes; rescan correlates every frozen target and is repeat-safe.
6. Keep janitor enumeration/removal capability separate from creation/selection. Add `scan`, `plan`, `dry-run`, `apply --plan-digest`, and `rescan`; document the scan → inspect/edit → dry-run/digest → apply → rescan routine, exact warning, `-w` handling, record location, auth boundaries, unsupported behavior, and irreversible external deletion.
7. Implement in order: companion preflight; strict scope/schema/account/migration/lease rules; pure domain/store/fakes; token/lease/results; companion capability matrix; CLI/docs/tests; typecheck/Vitest and only then a read-only live scan/plan/dry-run when the companion is available. Cover profile/preflight and auth boundaries, canonical plans/account switching, exact/legacy/multi-workspace protection, corrupt store/retention, token/lease races, concurrent applies, route drift, output counts, `-w` compatibility, and repeat-safe rescan.

## Exclusions

No release/tag action, TeamAI pin/adoption, or changes to `custom-runtime-release` or `custom-runtime-tag-publication` are planned. No resource mutation occurs before a future human-reviewed plan marks an exact entry `delete`, dry-run supplies its digest, and apply reaches its destructive boundary.
